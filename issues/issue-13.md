## 背景 / Background

前端人物关系图谱需要节点与边的结构化数据，大规模图谱每次全量查询开销大，需要缓存策略。

## 需求描述 / Description

实现图谱数据的查询接口与缓存机制。

## 任务清单 / Tasks

- [ ] 实现 `GET /api/works/{id}/graph`：返回 `nodes[]`（含 id、name、weight）与 `edges[]`（含 source、target、weight）
- [ ] 实现 `GET /api/works/{id}/characters`：人物列表，按总频次降序
- [ ] 实现 `GET /api/characters/{id}`：人物详情，含出场曲线数据与主要关系列表
- [ ] 实现缓存：图谱数据按 `work_id` 缓存，分析完成后失效重建
- [ ] 实现分页与节点数上限保护，避免超大规模图谱一次性返回
- [ ] 补充接口集成测试与缓存命中测试

## 验收标准 / Acceptance Criteria

- [ ] 对含 5 个人物、4 条关系的测试作品，接口能返回 5 个节点与 4 条边，且边权重与共现次数一致
- [ ] 当作品已完成分析时，能在 3 秒内返回 100 节点规模的图谱数据
- [ ] 第二次请求同一作品的图谱时，能命中缓存且响应时间显著低于首次
- [ ] 当分析任务更新了关系数据后，缓存能失效并在下次请求时返回新数据
- [ ] 当查询不存在的人物 ID 时，能返回 404
- [ ] 当图谱节点数超过上限时，能按权重截断返回并在响应中标记已截断
