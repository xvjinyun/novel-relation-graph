## 背景 / Background

采集任务可能因中断、重试或定时调度而重复执行，若无去重机制会产生重复章节数据，污染人物频次统计与关系权重。

## 需求描述 / Description

实现基于 URL 指纹的增量抓取机制，确保重复运行采集任务不产生重复数据。

## 任务清单 / Tasks

- [ ] 实现 URL 指纹计算（规范化 URL 后取 SHA-256），建立 `crawl_record` 表记录已采集指纹与采集时间
- [ ] 实现采集前的指纹查重，命中则跳过；支持 `--force` 参数强制重采
- [ ] 实现章节级别的幂等写入：以 `(work_id, chapter_no)` 联合唯一约束保证不产生重复章节
- [ ] 实现采集统计：本次新增章节数、跳过数、失败数，写入任务记录
- [ ] 补充单元测试覆盖：首次采集、重复运行、强制重采三种场景

## 验收标准 / Acceptance Criteria

- [ ] 首次运行采集任务后，数据库中能出现该作品的全部章节记录
- [ ] 在不修改源站内容的前提下重复运行同一采集任务，数据库中章节总数能保持不变，且不产生重复行
- [ ] 当源站新增一章后再次运行，能只采集新增的那一章，新增数统计为 1
- [ ] 使用 `--force` 参数运行时，能重新采集并更新已有章节
- [ ] 当同一章节被并发写入时，能依靠唯一约束保证最终只有一条记录，不产生重复
- [ ] 单元测试覆盖上述全部场景并全部通过
